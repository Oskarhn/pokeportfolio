Sources for the endpoint and header are third-party guides only, because Stitch's own setup page is
client-rendered and returned nothing but its title when fetched (2026-09-24); Google's
`stitch-skills` README describes itself as not an officially supported Google product. Treat the
details as likely, and let the disposable check in step 4 decide.

1. In Stitch, open the profile/settings menu and create an **API key**. Copy it once.
2. Put it in a **user environment variable** through the Windows GUI (Settings → System → About →
   Advanced system settings → Environment Variables → User variables → New: `STITCH_API_KEY`).
   Do not type it into a shell command line (history) or a chat.
3. Re-register the server so the header reads the variable instead of holding the key. In a normal
   terminal (not this chat):

   ```powershell
   claude mcp remove stitch
   claude mcp add stitch --transport http https://stitch.googleapis.com/mcp --header "X-Goog-Api-Key: ${STITCH_API_KEY}" -s user
   ```

   Claude Code documents `${VAR}` expansion for MCP configuration files (`.mcp.json`); it was **not
   verified** here for a user-scope `--header`. If the check in step 4 still fails, use the app's
   Connectors screen and paste the key there instead.
4. Start a **new** session and ask for exactly one disposable read-only `list_projects` call. A list
   (even an empty one) means authenticated. Anything else: stop and report the error text only.
5. Check the Stitch/Google side for billing or quota before any generation. `COST_POLICY.md` allows
   $0: a paid tier, billing account or overage is an owner decision, not a default.
